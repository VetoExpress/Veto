# Cloudflare 10000 席业务压测

2026-11-11 22:39–22:55（Asia/Shanghai），目标为 `https://api.miaoyww.top/v1`，部署版本 `ff8d84cd-0e41-4516-b65e-c18c0dc5d7b3`。
测试使用 10 个独立大会、每大会 1000 席，共 10000 个独立席位；600 秒逐步接入，随后 300 秒共同在线窗口。
测试前真实 HTTPS/WSS 烟测已通过，包含新闻、指令、局势和 R2 文件基本流程。

测试结束后十个专用大会均已关闭并软删除，测试文件按清理流程处理，测试组织者会话已撤销。诊断开关已关闭；当前线上健康检查 200，未返回 Server-Timing 或错误分类头。

## 结论

认证成功 **10000/10000**，但共同在线窗口实际为 **9999/10000**，严格的万人共同在线验收失败 1 席。窗口中出现 1 次 WebSocket 错误和 1 次关闭。

这轮共记录 106595 个 HTTP 请求，46840 成功，59755 失败。业务失败的主要根因已通过脱敏错误分类定位为 **`D1_OVERLOAD`**；随后压测端队列堆积，又产生了大量 `TimeoutError`，同时出现 `EADDRINUSE`，说明本机短连接/临时端口资源也耗尽。

| 错误分类                                |  次数 | 含义                               |
| --------------------------------------- | ----: | ---------------------------------- |
| `D1_OVERLOAD`                           | 25917 | Worker 进入业务代码后，D1 过载     |
| `TimeoutError`                          | 30145 | 压测端请求排队或等待超过 30 秒     |
| `EADDRINUSE`                            |  3668 | 压测机本地连接/临时端口资源耗尽    |
| `FILE_SUBMIT_FAILED`                    |     4 | 文件提交阶段失败，伴随 D1 过载场景 |
| `ETIMEDOUT` / `UND_ERR_CONNECT_TIMEOUT` |    21 | 压测机连接建立超时                 |

因此，本轮已经明确证明：**10000 席在线时，D1 是首个服务端瓶颈；D1 过载又把请求推入客户端队列，之后叠加了压测机连接资源问题。** 这不是单纯的前端或 WebSocket 连接问题。

## 三类业务流程

每个大会安排 5 个新闻作者、5 个指令处理席位和 1 个独立读取席位；作者、处理者、读取者使用不同席位。每类计划 50 条完整流程，共 150 条：

- 新闻：提交 → 作者获取自己的提交 → 处理席位获取待审核列表 → 审核发布 → 其他席位读取已发布新闻 → 作者读取最终状态。
- 指令：获取目标委员会 → 提交 → 作者获取 → 目标委员会获取 → 另一席位认领 → 批准或驳回 → 作者获取最终状态 → 读取修订记录。
- 局势：IPC 席位发布 → 其他席位读取局势 → 校验内容、来源大会、来源席位、状态和模拟时间。

| 流程     | 完成 / 计划 | 说明                                       |
| -------- | ----------: | ------------------------------------------ |
| 新闻     |      0 / 50 | 提交或后续读取阶段遭遇 D1 过载和超时       |
| 指令     |      0 / 50 | 目标获取、提交或处理阶段遭遇 D1 过载和超时 |
| 局势     |      4 / 50 | 少量流程完整发布并被其他席位读取           |
| 文件校验 |      1 / 50 | 其余上传、审核、下载被 D1 过载或超时打断   |

低负载云端烟测中，三类流程分别用约 0.9–3.6 秒完成并通过内容校验；因此本轮三类业务失败是高并发条件下的容量问题，不是流程脚本没有覆盖。

## 延迟与请求失败

接入阶段没有失败：认证 10000 次全部成功，初始委员会加载 9999 次成功。接入阶段客户端没有排队，说明登录和 WebSocket 建立在该接入速率下可以工作。

进入共同在线窗口后，读取类请求被 10000 个席位分散触发，但每个请求都需要 D1 权限查询和业务列表查询。主要请求结果如下：

## 压测机限制

压测机使用 Node.js、undici、ws 和 128 个 HTTP 并发连接槽位，同时维持约 10000 条 WebSocket。到窗口后段，HTTP 队列超过 10000，出现 3668 个 `EADDRINUSE`，并伴随少量连接建立超时。它们不能归因于 Cloudflare。

这不掩盖 D1 过载：`D1_OVERLOAD` 在客户端端口耗尽之前已经出现，并且覆盖新闻、局势、文件、指令多个列表接口。下一轮如果要测 Cloudflare 的上限，应拆分发压机或降低单机业务请求并发，避免客户端资源问题覆盖服务端数据。
